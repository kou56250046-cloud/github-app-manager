# ローカル起動ポートの表示 — 要件

## 背景

`~/projects/PORTS.md` に、ローカルで起動するアプリのポートを重複なしで割り当てた一覧がある。
ただしアプリを開くたびに Markdown を探して読む必要があり、どの URL で開くかを
ダッシュボードから直接たどれない。スキャン時に PORTS.md を取り込み、カードと詳細画面に出す。

## 受入条件

- [ ] `pnpm scan:local` を実行すると、`data/projects.local.json` の各プロジェクトに `ports` 配列が付く。
      PORTS.md に行があるプロジェクトは 1 件以上、無いプロジェクトは空配列になる
- [ ] 1 プロジェクトに複数の行がある場合（例: ai-scraping の 5173 と 8787）は全部が `ports` に入る
- [ ] 「プロジェクト」列の全角括弧の注記（例: `ai-scraping（AI Radar 画面）`）は外してディレクトリ名と照合し、
      注記は `label` として残す
- [ ] PORTS.md の「帯域」表は取り込まない。「## 一覧」配下の表だけを読む
- [ ] PORTS.md が無い、または表が壊れていてもスキャンは失敗しない（全件 `ports: []`）
- [ ] カード下部に、ポートごとの「:5178 ↗」リンクが出る。クリックすると「開く URL」列の URL が新しいタブで開き、
      詳細モーダルは開かない。リンクにマウスを乗せると注記が出る（`title` 属性。例: 「AI Radar 画面」）
- [ ] ポートが 2 つ以上あるカード（ai-scraping、ai-tech）では、ポートが 1 か所にまとまって並ぶ。日付・公開ページのリンクとの間隔が崩れない
- [ ] 「開く URL」が `http(s)://` で始まらない行（file-cleaning の「ブラウザでは開かない」）は、カードではリンクにせず `:5183` の文字だけを出す。
      この文字はクリックしても特別な動作をしない（カードの他の場所と同じく詳細が開く）
- [ ] 詳細モーダルの「基本情報」に「ローカル起動」の行が出る。各ポートについて、ポート番号・注記・起動方法・設定の場所を表示する。
      「開く URL」が `http(s)://` で始まる場合はポート番号をその URL へのリンクにする。始まらない場合はリンクにせず、URL 列の文字（「ブラウザでは開かない」）を併記する
- [ ] ポートが無いプロジェクトでは、カードにも詳細にも何も出ない（空の枠や見出しを出さない）
- [ ] `pnpm publish:pages` で生成される `docs/projects.public.json` に `ports` が含まれない。漏洩チェックに `"ports"` キーを足し、万一含まれたら失敗させる

## 非目標

- 画面からポートを編集すること（PORTS.md を正とし、手で書き換える）
- `data/projects-meta.json` によるポートの手動上書き
- ポートが今使われているか（サーバーが起動中か）を確かめて表示すること
- ダッシュボードからアプリを起動・停止するボタン
- ポートでの絞り込みや検索（`filters.js` は触らない）
- PORTS.md と各プロジェクトの実際の設定（vite.config など）が食い違っていないかの検査
- 公開版（GitHub Pages）にポートを出すこと
- PORTS.md の変更を監視して自動で再スキャンすること（反映は既存の「再スキャン」ボタンか `pnpm scan` で行う）

## 制約

- npm 依存を足さない。素の JS で書く
- 公開版は許可リスト方式のまま。`PUBLIC_FIELDS` に `ports` を足さない
- 画面テキスト・コメントは日本語
